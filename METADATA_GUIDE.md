# AutoFlow AI Metadata System

## Overview

The metadata layer is the **single source of truth** for the AutoFlow AI platform.
All code generation across backend, frontend, infrastructure, and documentation
consumes these metadata definitions. Nothing should be hardcoded.

### Architecture Flow

```
metadata/*.yaml  ->  MetadataLoader  ->  IntermediateModel  ->  Generators  ->  Code
       |
  MetadataValidator
       |
  Validation Report
```

## Directory Structure

```
metadata/
  entities/      # Database models and schemas (18 entity files)
  services/      # Business logic services (12 service files)
  api/           # REST API endpoints (8 API files)
  permissions/   # RBAC roles and policies (3 files)
  workflows/     # Workflow templates, states, retry policies (4 files)
  connectors/    # External service integrations (26 connector files)
  ai/            # AI/ML models, agents, prompts, planner (12 files)
  ui/            # Frontend forms, tables, navigation, themes (6 files)
  events/        # Domain events + bus config (8 files: bus.yaml, platform_events.yaml, workflow.yaml, user.yaml, organization.yaml, connector.yaml, notification.yaml, system.yaml)
  plugins/       # Plugin SDK metadata (1 file)
  middleware/    # FastAPI middleware stack (1 file)
  runtime/       # Workflow runtime tuning config (1 file: config.yaml)
```

## Connectors (26)

Email/chat: Gmail, Outlook, Slack, Discord, Teams · Dev tools: GitHub,
GitLab, Jira, Linear · Docs: Notion, Confluence · Storage: Google Drive,
Dropbox, OneDrive · Payments: Stripe, Shopify, PayPal · Database: Airtable,
PostgreSQL, MySQL, MongoDB, Redis · Generic: REST, GraphQL, gRPC, Webhook

Each connector YAML defines the full schema: name, version, authentication,
supported_scopes, actions, triggers, polling, webhooks, rate_limits,
retry_policy, timeouts, supported_events, supported_objects, pagination,
batching, streaming, capabilities, permissions, health_check,
documentation, deprecation_policy. The connector framework
(`backend/app/connectors/`) is generated by
(`scripts/generators/backend/connector_generator.py`) and emits a
multi-tenant SDK (BaseConnector), registry/factory/manager/loader/discovery,
auth strategies, execution resilience helpers, transports, observability,
security, and 26 metadata-driven connector implementations. Validate with:

```bash
python scripts/validate_connectors.py
```

## AI (12 files)

models.yaml, agents.yaml, prompts.yaml, memory.yaml,
planner.yaml, optimizer.yaml, workflow_generator.yaml,
reasoning.yaml, constraints.yaml, optimization.yaml,
providers.yaml, examples.yaml

The AI planner (`backend/app/ai/planner/`) is generated from
`metadata/ai/*.yaml` by `scripts/generators/backend/ai_planner_generator.py`
(28 planner modules + 9 LLM provider modules under `backend/app/ai/providers/`).
The planner converts natural language into deterministic, validated
`WorkflowPlan` specifications consumed by the Workflow Runtime; it reasons
and plans only and never executes. `providers.yaml` drives the
`BaseLLMProvider` abstraction (OpenAI, Anthropic, Gemini, OpenRouter,
Ollama, vLLM) so the planner never depends on a concrete SDK. Build +
validate with:

```bash
python scripts/build_ai_planner.py
python scripts/generate.py backend.ai --force
python scripts/validate_ai_planner.py
```

## Runtime

The workflow runtime (`backend/app/runtime/`) is generated from
`metadata/runtime/config.yaml` plus `metadata/workflows/*.yaml`
(templates, execution states, retry policies). The generator
(`scripts/generators/backend/runtime_generator.py`) emits 19 modules:
compiler, executor, scheduler, graph, dag, nodes, edges, state,
checkpoint, rollback, retry, parallel, queue, worker, metrics, events,
monitor, locks, serializer. Validate with:

```bash
python scripts/validate_runtime.py
```

## Events (23 domain events across 8 files)

Event definitions are split by domain: `workflow.yaml` (workflow.started,
workflow.completed, workflow.failed, execution.retried), `user.yaml`
(user.created, user.updated, user.deleted), `organization.yaml`
(organization.created, organization.updated, organization.deleted),
`connector.yaml` (connector.connected, connector.disconnected,
connector.error), `notification.yaml` (notification.sent,
notification.failed), `system.yaml` (system.health_ok, system.error),
and `platform_events.yaml` (invoice.paid, subscription.cancelled,
ai.workflow_generated, ai.workflow_optimized, connector.action_executed,
connector.trigger_fired). Bus config + handler assignments live in
`bus.yaml`. Idempotent events (workflow.started, invoice.paid,
user.created, organization.created) get deterministic idempotency keys
and are deduplicated by the bus.

## Validation

Run full metadata validation:

```bash
python -c "
from scripts.generators.common.metadata_validator import MetadataValidator
v = MetadataValidator(metadata_dir='metadata')
v.validate_all()
print(v.summary())
"
```

## Best Practices

1. One entity per YAML file
2. Use enums instead of raw strings for constrained values
3. Define bidirectional relationships with back_populates
4. Mark sensitive fields (passwords, tokens) with sensitive: true
5. Set tenant: true for organization-scoped entities
6. Define validation rules in service methods blocks
7. Specify rate limits on API endpoints
8. Always provide descriptions for entities, fields, and endpoints
