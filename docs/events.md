# AutoFlow AI - Event Bus

> Generated by the **Event Bus Generator** from `metadata/events/*.yaml`.

This document describes the metadata-driven in-process event bus. Events are
published with `publish()`, delivered to subscribed handlers with retry and
dead-letter handling, persisted for replay, versioned, and deduplicated via
idempotency keys.

## Architecture

```
publish() -> EventBus -> EventStore (persist) -> EventDispatcher -> handlers
                                                          |-- retry on failure
                                                          `-- DeadLetterQueue (exhausted)
replay()/retry() re-dispatch persisted or dead-lettered events
```

```yaml
  storage: memory

  enabled: true

  base_delay: 0.5
  max_delay: 10.0
  backoff_factor: 2.0

  enabled: true

  enabled: true
```

## Publishing Events

```python
from app.events import Event, publish

event = Event(
    event_type="workflow.started",
    entity_id="wf-123",
    payload={"workflow_id": "wf-123", "execution_id": "ex-1", "triggered_by": "user-1"},
)
await publish(event)
```

Events declared `idempotent: true` in metadata get an idempotency key
derived from their payload automatically; re-publishing the same logical
event raises `DuplicateEventError`.

## Subscribing

```python
from app.events import subscribe, unsubscribe

def on_workflow_started(event):
    print(event.payload)

subscribe("workflow.started", on_workflow_started)
unsubscribe("workflow.started", on_workflow_started)
```

Handlers may be sync or async. The `@subscriber` decorator offers a
declarative form:

```python
from app.events import subscriber

@subscriber("invoice.paid")
async def send_receipt(event): ...
```

## Handler Priority

Handlers for the same event type run in descending priority order (higher
priority first, stable within equal priorities):

```python
from app.events import subscribe

subscribe("workflow.started", handler_a, priority=10)  # runs first
subscribe("workflow.started", handler_b, priority=1)
```

## Request & Correlation IDs

Every published event carries a `request_id`. When omitted it is generated
automatically and the `correlation_id` defaults to it, so events can be
traced back to a request:

```python
event = Event(event_type="workflow.started", request_id="req-abc",
                 correlation_id="corr-xyz")
```

## Tracing

The bus records a trace per published event with one span per handler
invocation (duration + outcome). Inspect live traces with:

```python
from app.events import tracer

traces = tracer.list()  # newest first
trace = tracer.get(trace_id)
```

## Metadata Handlers

Handlers declared in `metadata/events/*.yaml` (`handlers:` section) are
registered automatically when the bus is constructed:

| Handler | Module | Purpose |
|---------|--------|---------|
| analytics | `app.events.handlers.analytics` | Aggregates event volume metrics |
| audit | `app.events.handlers.audit` | Records domain events into the audit trail |
| connector | `app.events.handlers.connector` | Tracks connector lifecycle transitions |
| notification | `app.events.handlers.notification` | Queues outbound notifications |
| webhook | `app.events.handlers.webhook` | Queues outbound webhook deliveries |
| workflow | `app.events.handlers.workflow` | Tracks workflow outcomes and retry suggestions |

## Replay & Retry

```python
from app.events import replay, retry

await replay(event_type="workflow.failed")  # re-dispatch persisted events
await retry(event_id="...")                 # retry a dead-lettered event
```

## Validation

Run the complete 9-step validation pipeline:

```bash
python scripts/validate_events.py
```

1. AST parsing of every generated `backend/app/events/*.py` and test file.
2. Import check of `app.events.*` with `PYTHONPATH=backend`.
3. Startup validation (EventBus construction + metadata handler registration).
4. Event registration check (`METADATA_SUBSCRIPTIONS` vs metadata).
5. Publish/subscribe integration tests (incl. handler priority, request IDs).
6. Retry tests.
7. Dead-letter tests.
8. Replay tests.
9. Coverage report (stdlib trace).
